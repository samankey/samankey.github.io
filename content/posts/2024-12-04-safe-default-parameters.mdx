객체를 매개변수로 받아 바로 구조분해하는 함수가 있다. 호출하는 쪽에서 그 인자를 빼먹으면 어떻게 되는지, 그리고 어떻게 막는지 정리한다.

## 인자를 빼먹으면 터진다

```js
async function getRevieweeList({ commit }, { lastViewReviewPopDate = '', excludeMeetAgainHelper = false }) {
  // ... 함수 로직
}

getRevieweeList({ commit });
```

```text
TypeError: Cannot read properties of undefined (reading 'lastViewReviewPopDate')
```

두 번째 인자가 없으면 그 값은 `undefined`다. `undefined`에서 프로퍼티를 꺼낼 수 없으므로 구조분해가 실패한다. 패턴 안에 `= ''` 같은 기본값을 적어둔 것은 도움이 되지 않는다. 그 기본값은 **꺼낸 프로퍼티가 없을 때** 쓰이는 것이고, 여기서는 꺼낼 대상 자체가 없다.

실제로 이런 상황이 자주 생긴다.

- API 호출 시 파라미터를 깜빡하고 안 보냈을 때
- 테스트 코드에서 일부 파라미터만 넣어보고 싶을 때
- 다른 사람이 이 함수를 호출할 때

## 객체를 받고 안에서 구조분해하기

매개변수에 기본값을 주고, 구조분해는 함수 안에서 한다.

```js
async function getRevieweeList({ commit }, options = {}) {
  const {
    lastViewReviewPopDate = '',
    excludeMeetAgainHelper = false
  } = options;
  // ... 함수 로직
}

getRevieweeList({ commit }); // 정상 동작, options 는 빈 객체
```

인자가 없으면 `options`가 `{}`가 되고, 빈 객체에서 프로퍼티를 꺼내면 없으니 각각의 기본값이 쓰인다.

## 구조분해 매개변수에도 기본값을 줄 수 있다

앞의 방식은 줄이 늘어난다. 그런데 줄일 방법이 있다. 구조분해 패턴 **전체**에 기본값을 붙이면 된다.

```js
async function getRevieweeList({ commit }, { lastViewReviewPopDate = '', excludeMeetAgainHelper = false } = {}) {
  // ... 함수 로직
}

getRevieweeList({ commit }); // 정상 동작
```

`= {}` 하나가 전부다. 맨 처음 방식과 길이가 같고, 두 번째 방식과 안전성이 같다. 안쪽의 `= ''`는 프로퍼티가 없을 때의 기본값이고, 바깥의 `= {}`는 **인자 자체가 없을 때**의 기본값이다. 층이 다르니 둘 다 필요하다.

## null은 기본값이 막아주지 않는다

기본 매개변수는 값이 `undefined`일 때만 쓰인다. `null`은 엄연히 전달된 값이므로 기본값이 발동하지 않고, `null`에서 프로퍼티를 꺼내려다 그대로 터진다.

네 가지 형태를 호출 방식별로 확인했다.

| 호출 | `{ … }` | `options = {}` | `{ … } = {}` | `options ?? {}` |
| --- | --- | --- | --- | --- |
| `f()` | TypeError | ok | ok | ok |
| `f(undefined)` | TypeError | ok | ok | ok |
| `f(null)` | TypeError | **TypeError** | **TypeError** | ok |
| `f({})` | ok | ok | ok | ok |

`null`까지 막아야 한다면 기본값이 아니라 병합이 필요하다.

```js
async function getRevieweeList({ commit }, options) {
  const {
    lastViewReviewPopDate = '',
    excludeMeetAgainHelper = false
  } = options ?? {};
  // ... 함수 로직
}
```

`null`이 올 수 있는지는 호출하는 쪽을 보면 알 수 있다. API 응답을 그대로 넘기거나, 값이 없을 때 `null`을 쓰는 코드와 맞닿아 있다면 `?? {}`가 필요하다. 그렇지 않다면 `= {}`로 충분하다.

## async 함수라면 TypeError가 보이지 않는다

위 함수는 `async`다. `async` 함수 안에서 난 에러는 던져지는 대신 **거부된 Promise**가 된다.

```js
getRevieweeList({ commit }); // await 도 catch 도 없다
```

이러면 콘솔에 `TypeError`가 아니라 처리되지 않은 Promise 거부로 남는다. `window.onerror`로는 오지 않고 `unhandledrejection` 이벤트로 오기 때문에, 에러 수집 도구가 그 이벤트를 듣지 않으면 아무 기록도 남지 않는다. 같은 이야기를 [try-catch 내에서 의도적인 지연을 시켜야할 때](/blog/try-catch-with-async-delay)에서 더 자세히 다뤘다.

Vuex 액션처럼 호출 결과를 `await`하지 않고 부르는 자리가 많은 코드라면, 인자를 빼먹은 버그가 조용히 지나갈 수 있다는 뜻이다.

## 에러 메시지 두 가지

구조분해 패턴에 기본값이 있는지에 따라 메시지가 다르다.

```js
const { a } = undefined;
// Cannot destructure property 'a' of 'undefined' as it is undefined.

const { a = 1 } = undefined;
// Cannot read properties of undefined (reading 'a')
```

기본값이 있으면 엔진이 프로퍼티를 먼저 읽으려 하기 때문에 뒤쪽 메시지가 나온다. 둘 다 원인은 같다.

## 정리

- 구조분해 패턴 안의 기본값은 **프로퍼티가 없을 때** 쓰인다. 인자 자체가 없는 경우는 막아주지 않는다
- 패턴 전체에 `= {}`를 붙이면 짧게 쓰면서 막을 수 있다 — 객체를 받아 안에서 다시 구조분해할 필요가 없다
- 기본값은 `undefined`에만 발동한다. `null`이 올 수 있으면 `?? {}`로 병합해야 한다
- `async` 함수에서는 이 에러가 처리되지 않은 Promise 거부가 되어 조용히 사라질 수 있다
