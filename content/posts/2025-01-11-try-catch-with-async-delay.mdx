정산을 요청한 뒤 3초 기다리고 데이터를 다시 불러와야 했다. `try` 블록 안에 `setTimeout`을 넣었고, 콜백에서 에러가 나면 아래 `catch`가 잡아줄 거라고 생각했다.

```js
/** 정산요청 */
async requestSettlement(type) {

  ...

  try {
    this.$nuxt.$loading.start(0, 'settlement');

    // 정산 함수 호출
    await putImmediatePayroll();

    // ============================= //
    // 3초 지연 후 콜백함수 실행
    // 콜백함수 내부에 error가 throw 되면 catch에서 잡힐거라 예상
    setTimeout(async () => {
      await this.getPayrollData(); // 데이터 페칭
      ...
    }, 3000);
    // ============================= //

  } catch (error) {
    console.error('정산 요청 중 오류 발생:', error);
    this.ajaxError(error);
  } finally {
    this.$nuxt.$loading.finish();
  }
}
```

## 문제

1. error를 잡지 못함
2. `finally`가 먼저 실행됨

## 실행 과정

1. `try` 블록이 실행되고 `setTimeout` 호출
2. `setTimeout`은 Web API로 전달되고, 3초 후 콜백 함수를 태스크 큐에 추가하도록 예약
3. `try-catch` 블록의 실행이 즉시 완료되고 콜스택에서 제거 — 이때 `finally`가 실행된다
4. 3초 후 이벤트 루프가 태스크 큐에서 `setTimeout`의 콜백을 가져와 콜스택에 추가
5. 콜백 함수가 실행됨
6. 에러가 발생하면 이미 `try-catch` 블록이 콜스택에서 사라졌기 때문에 에러는 캐치되지 않는다

`try`는 **블록을 감싸는 것이 아니라 그 블록이 실행되는 동안을 감싼다.** `setTimeout`은 콜백을 예약하기만 하고 즉시 반환하므로, `try`가 지켜보는 시간은 3초가 아니라 예약을 마치기까지의 순간이다. 로딩 인디케이터도 정산이 끝나기 3초 전에 꺼진다.

### 에러는 어디로 가는가

원래 코드의 콜백에는 `await`이 있으므로 콜백은 `async`여야 한다. 일반 화살표 함수 안에 `await`을 쓰면 실행 전에 문법 오류가 난다.

콜백이 `async`인지에 따라 잡히지 않은 에러가 가는 곳이 다르다.

```js
setTimeout(() => { throw new Error('plain 콜백'); }, 50);
setTimeout(async () => { throw new Error('async 콜백'); }, 100);
```

```text
finally 실행 (t=0)
uncaughtException : plain 콜백
unhandledRejection: async 콜백
```

일반 함수의 `throw`는 잡히지 않은 예외가 되고, `async` 함수의 `throw`는 그 함수가 반환한 Promise의 거부가 된다. 아무도 그 Promise를 받지 않으므로 처리되지 않은 거부가 된다.

후자가 더 조용하다. 브라우저 콘솔에는 남지만 `window.onerror`로는 오지 않고 `unhandledrejection` 이벤트로 온다. 에러 수집 도구가 그 이벤트를 듣지 않으면 아무 기록도 남지 않는다.

## 고친 코드

`setTimeout`을 Promise로 감싸고 `await`한다. 그러면 지연도 `try`가 지켜보는 시간 안으로 들어온다.

```js
async requestSettlement(type) {

  ...

  try {
    // 로딩시작
    ...
    // 정산 함수 호출
    ...

    // ============================= //
    // 정산 3초 대기
    await new Promise((resolve) => setTimeout(resolve, 3000));

    // 나머지 코드
    ...
    // ============================= //

  } catch (error) {
    console.error('정산 요청 중 오류 발생:', error);
    this.ajaxError(error);
  } finally {
    this.$nuxt.$loading.finish();
  }
}
```

지연 뒤의 코드가 콜백이 아니라 `try` 블록 안에 그대로 남는다는 점이 핵심이다. 에러는 `catch`로 오고, `finally`는 전부 끝난 뒤에 실행된다.

여러 곳에서 쓴다면 이름을 붙여두면 읽기 쉽다.

```js
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

await delay(3000);
```

## 비동기와 try-catch를 함께 쓸 때

같은 함정이 여러 모양으로 나타난다.

### 타이밍 문제

```js
try {
  setTimeout(() => {
    throw new Error("비동기 에러");
  }, 1000);
} catch (error) {
  console.error("이 catch 블록은 에러를 잡지 못합니다:", error);
}
```

앞의 경우와 같다. `try`는 예약이 끝난 시점에 이미 할 일을 마쳤다.

### 비동기 콜백에서의 에러 처리 누락

```js
try {
  fs.readFile('nonexistent.txt', (err, data) => {
    if (err) throw err;
    console.log(data);
  });
} catch (error) {
  console.error("이 catch 블록은 콜백 내부의 에러를 잡지 못합니다:", error);
}
```

콜백 함수 내부에서 발생한 에러는 외부의 `try-catch`로 잡을 수 없다. 콜백 스타일 API라면 에러를 콜백 안에서 처리하거나, Promise를 반환하는 쪽(`fs.promises.readFile`)으로 바꿔 `await`한다.

### Promise 체인에서의 에러 전파

```js
Promise.resolve()
  .then(() => {
    try {
      throw new Error("에러 발생");
    } catch (error) {
      console.error("에러를 여기서 잡았습니다:", error);
    }
  })
  .catch(error => {
    console.error("이 catch 블록은 실행되지 않습니다:", error);
  });
```

이쪽은 잡지 못하는 게 아니라 **이미 잡혀서 더 가지 않는** 경우다. `then` 안에서 처리했으므로 체인의 `.catch`에는 도달할 것이 없다. 로그만 남기고 위로도 알리려면 `catch` 안에서 다시 `throw`해야 한다.

### async/await 사용 시 주의점

```js
async function fetchData() {
  throw new Error("비동기 함수 내부 에러");
}

try {
  fetchData(); // 이 호출은 try-catch로 잡히지 않음, await가 있다면 잡힘
} catch (error) {
  console.error("이 catch 블록은 에러를 잡지 못합니다:", error);
}
```

`async` 함수는 던지는 대신 거부된 Promise를 반환한다. `await`이 그 거부를 다시 예외로 바꿔주므로, `await` 없이 부르면 `catch`가 볼 것이 없다. 이때도 처리되지 않은 거부로 남는다.

## 정리

- `try`는 블록이 아니라 **그 블록이 실행되는 동안**을 감싼다. 예약만 하고 반환하는 것은 감싸지지 않는다
- `try` 안의 `setTimeout` 콜백에서 난 에러는 `catch`가 못 잡고, `finally`는 콜백보다 먼저 실행된다
- 지연은 `await new Promise((resolve) => setTimeout(resolve, ms))`로 만들어 `try` 안에 들여놓는다
- 콜백이 `async`면 에러가 예외가 아니라 처리되지 않은 Promise 거부가 된다 — 더 조용히 사라진다
- `async` 함수 호출에 `await`을 빼면 `try-catch`를 그냥 통과한다
